# IR 规范 —— 图的结构化中间表示

> **IR 是这个 skill 的核心资产。** 它不是"画图指令"，是
> **把「物理意图」翻译成「可执行规格」的那一层**。
>
> 关键性质：**IR 与后端无关。** 同一份 IR，可以交给 SVG、Blender、
> Illustrator、matplotlib、TikZ 任一后端执行。后端可换，IR 不变。

---

## 为什么需要 IR

老师原话：

> "生成和你的输入**一样（结构/物理内容）**，但输出**高标准（排版/光影）**的图"

这句话把问题拆成了两个正交的层：

```
结构/物理内容  ←── 来自输入（参考图 / 草图）──→  IR 的 figure 层
排版/光影      ←── 来自样式规范 ──────────────→  IR 的 style 层
怎么画出来      ←── 后端选择 ─────────────────→  IR 的 execution 层
```

**没有 IR 会怎样**：AI 直接画 → 画得漂亮但物理是错的。
这正是老师警告的"花里胡哨但物理表达不准确"。

**IR 的作用**：强制在动手前把物理内容写清楚，让"物理正确"成为
流程里的**强制约束**，而不是靠人盯着。

---

## 两条独立轴：内容 × 风格

后端选择要同时看两条轴，**它们互相独立**：

```
内容轴  这张图在物理上是什么   →  示意图 / 定量图 / 复合
风格轴  这张图应该长什么样     →  矢量插画 / 半写实 / 照片级 / 手绘 / 扁平信息图
```

**同样内容换风格，最佳后端就变**。例：内容都是"碰撞示意"——

| 风格 | 后端 |
|---|---|
| 矢量插画（平涂 + 渐变 + 描边） | `svg` / `illustrator` |
| 半写实科学插画（有质感光影） | `blender`(toon) / `imagegen` |
| 照片级渲染 | `blender` |
| 手绘 / 艺术风 | `imagegen` |
| 扁平信息图 | `svg` |

> ⚠️ 这是 `nature-figure` 的局限所在：它把后端锁死在 Python/R，
> 因为它默认了**风格只有"数据可视化"一种**。本 IR 显式地把风格独立成轴。

### 风格分类表

| 风格类 | 判据（能否从参考图看出来） | 首选后端 |
|---|---|---|
| `矢量插画` | 平涂或线性渐变；清晰统一描边；**无材质纹理**；明暗是画出来的不是算出来的 | svg / illustrator |
| `半写实插画` | 有质感与光影层次，但形体仍示意性 | blender(toon) / imagegen |
| `照片级渲染` | 真实材质、真实光照、景深 | blender |
| `手绘/艺术` | 笔触、不规则边缘、非几何 | imagegen |
| `扁平信息图` | 纯色块、图标化、无描边或极细描边 | svg |
| `数据可视化` | 坐标轴 + 刻度 + 图例 + 统计表达 | matplotlib / ROOT |

**关键**：风格分类必须给出**判据**，不能只写一个词。
判据要能被别人复核——"我说它是矢量插画，因为圆柱的明暗是手绘渐变而非光照计算"。

## 六层结构

```yaml
figure:       # ① 物理层：这张图表达什么（后端无关）
elements:     # ② 元素层：由哪些东西构成、各自的物理含义（后端无关）
composition:  # ③ 构图层：放在哪、多大、什么视角（后端无关）★实测补充
style:        # ④ 风格层：分类（驱动选型）+ 参数（供执行）
execution:    # ⑤ 执行层：选哪个后端、为什么、否决了谁
assertions:   # ⑥ 验收层：怎么判定做对了
```

> ⚠️ **`composition` 层是实测补上的。**
> 第一版 IR 只有 `figure + elements`，拿它复现 T3-07 的结果是：
> **内容全对、构图全错**——元素都在，但网格透视不对、小图位置飘了、比例失调。
> 教训：**"有什么"和"怎么排"是两件事，必须分开写。**

**① ② 两层完全后端无关。** 换后端时它们不动——
这正是"同一个 IR 可以交给 SVG / Blender / Illustrator"的含义。

## 完整格式

```yaml
figure:
  id: B1-T3-03
  source: "STAR Collab., Nature 635 (2024), Extended Data Fig. 1g"
  physics_claim: >
    一句话说明这张图要表达什么物理。
    例：碰撞中反应平面上的方位角 ϕ 定义与探测器构型。
  archetype: 示意图          # 定量面板 | 3D曲面 | 示意图 | 复合图
  panels_count: 2

elements:                    # ★ 画序 = z 序，从后往前写
  - id: E1
    name: 探测器外壳
    physics_role: >
      这个元素在物理上代表什么。必须写，这是防"花里胡哨"的关键。
      例：十二边形棱柱，代表 STAR 探测器的接受度覆盖。
    primitive: n棱柱(3D)     # 后端无关的几何描述，不写 API
    params:                  # 相对几何，不写绝对坐标
      n_faces: 12
      depth_offset: "左上, 约 0.09R"
      shell_scale: 1.055
    material: "银灰, 微弱金属感, 中心亮边缘暗"
    z: 1                     # 1 最靠后

  - id: E2
    name: 前表面
    physics_role: 探测器接受面
    primitive: n边形面 + 径向渐变
    material: "近白, 中心亮边缘转灰"
    z: 2

  # ... E3..En

geometry_constraints:         # ★★ 几何约束层：防"画得漂亮但物理错"
  # 为什么必须有这一层：
  #   构图层用"偏右上""靠近表面"这类词描述位置 —— 人看得懂，
  #   但实现时是**不可判定**的，AI 会画出一个"看起来对"但物理错的图。
  #
  #   实测踩坑（喷注淬火）：
  #     IR 只写"顶点偏右上" → 实现时逃逸喷注穿过了大半个介质，
  #     完全失去"逃逸"的物理意义。
  #
  #   改成可判定的数值约束后，才拦得住：
  #     顶点半径/介质半径 = 0.72
  #     逃逸喷注介质内路径 = 0.44 R（短）
  #     淬火喷注介质内路径 = 1.76 R（长）
  #
  #   规则：**凡是"物理上必须成立的关系"，都要写成可计算的量。**
  约束:
    - 名: 顶点偏离介质中心
      量: "距离(顶点, 介质中心) / 介质半径"
      要求: "> 0.65"
      为什么: "这是表面偏置——两个喷注路径长度差的原因"
    - 名: 逃逸喷注朝外
      量: "dot(喷注方向, 顶点→介质中心)"
      要求: "< 0"          # 点积为负 = 方向相反 = 朝外
      为什么: "朝外才能短路径逃逸"
    - 名: 路径长度比
      量: "淬火喷注介质内路径 / 逃逸喷注介质内路径"
      要求: "> 3"
      为什么: "路径差是能量损失差的物理基础"

composition:                  # ★ 构图层：脱离原图重建的关键
  canvas: {ratio: "约 1.36（横）", 用途: "单栏或双栏图"}
  视角: >
    说明这是正视图还是透视视图、俯仰角大概多少。
    例：以约 30° 俯角俯视反应平面，平面呈左低右高的平行四边形，
    消失点在图外右侧。
  分区: >
    画面分成哪几块，各占什么相对位置。
    例：左 1/5 为两个纵向排列的衰变小图；右 4/5 为主体场景。
  元素布局:                     # 用相对坐标（0-1），不用绝对像素
    # ⚠️ 尺寸必须说明【量的是什么】——否则实现会差好几倍。
    #    踩过的坑：写"火球直径 0.22 画布宽"，实现者按核心半径缩放，
    #    结果总尺寸变成 0.45 画布宽，火球炸掉整张图。
    #    正确写法："总直径（含弥散边缘）约 0.22 画布宽"，
    #    或分开写："核心直径 0.10 / 含弥散 0.22"。
    - id: E1
      锚点: [0.62, 0.52]        # 中心位置（画布相对坐标）
      相对尺寸: "宽约 0.55 画布宽"
    - id: E9
      锚点: [0.10, 0.24]
      相对尺寸: "高约 0.42 画布高"
      备注: "上下两个，间距约 0.35 画布高"
  叠放关系: >
    谁压住谁。例：火球压住网格但边缘弥散；粒子在火球之上；
    L̂ 箭头在所有元素最上层。

style:
  # ★ 风格分类 —— 驱动后端选型，必须给判据
  classification: 矢量插画
  evidence: >
    圆柱的明暗来自手绘的线性渐变而非光照计算；描边宽度统一；
    无材质纹理与真实反射。故归为矢量插画，而非半写实或照片级。
  characteristics:
    - 平涂 + 线性/径向渐变
    - 清晰统一描边
    - 无材质纹理
  # 以下为执行参数（供已选后端使用）
  palette:
    shell: "#ced2d9 → #a3a8b2"
    rim: "#8b9099"
    accent: "#3129b4"
    fireball_core: "#fff0cf → #fb9a52 → #f2703a"
    背景: "#ffffff"
  line_widths: {outline: 1.0, detail: 0.8, emphasis: 2.4}
  fonts:
    latin: "DejaVu Sans"      # 期刊图英文默认
    cjk: "Noto Sans CJK"      # 需中文标注时
    size_steps: [8, 10, 12.5, 17, 22]
  conventions:
    - "下标用 dy + 绝对字号，不用 baseline-shift"
    - "居中标签用 Unicode 下标字符，不用 tspan"

execution:                    # ★ 后端选择：两条轴共同决定
  primary: svg
  reason: >
    内容轴：无数据、形状是表达手段 → 指向 SVG。
    风格轴：矢量插画 → 指向 SVG/Illustrator。
    两轴一致，故 primary=svg。
  style_switch: >
    若风格改为「半写实科学插画」，同一份 figure + elements
    应改用 blender(toon shader) 或 imagegen，前两层无需改动。
  fallback: [illustrator, matplotlib]
  rejected:
    - tool: blender
      reason: "风格轴不符——默认产出照片级渲染，与矢量插画风格冲突"
    - tool: imagegen
      reason: "随机采样，无法保证与参考图逐结构一致"
    - tool: mathematica
      reason: "实测 3D 导出会栅格化，交不出投稿级矢量"
  portability: >
    figure + elements 两层完全后端无关。
    换后端（Blender / Illustrator / TikZ）时这两层不动。

assertions:
  machine:                    # AI 逐条自检并给证据
    - "E1..En 全部存在，无遗漏无多余"
    - "panel 数量与位置关系与参考一致"
    - "标注文字全部正确渲染，无豆腐块"
    - "渐变生效（抽查中心像素非纯黑）"
    - "导出为矢量，文字可提取"
  human:                      # 必须人看的
    - "物理表达准确"
    - "视觉达到可投稿水平"
```

## 后端选型规则（写进 IR 的 execution 层）

**规则：先问"这张图的形状是不是科学内容"。**

| 判据 | 后端 | 理由 |
|---|---|---|
| 有数据 + 坐标轴 | `matplotlib` | 真矢量（实测 1551 条指令，0 位图） |
| 3D 曲面（rainbow colormap） | `matplotlib` | **优于 Mathematica**——后者 3D 会栅格化 |
| 形状是表达手段（碰撞示意、流程） | `svg` | 真矢量 + 精确排版 + 可移植 |
| 形状是科学内容（探测器几何、CAD） | `blender` | 真 3D，手算投影替代不了 |
| 需要人工精修 | `illustrator` | 输出干净的 SVG，可直接打开编辑 |
| 无结构要求、只要感觉 | `imagegen` | 随机采样，只作概念/灵感 |

**关键**：后端选择写在 IR 里并**给出理由**。
理由是给老师看的——他能判断这个选型对不对。

---

## IR 的三个用途

1. **执行依据** —— 后端照着它画
2. **验收清单** —— assertions 逐条勾
3. **沟通载体** —— 拿给老师看："这张图我理解成这些元素，对吗？"

第 3 条可能最有用。**老师能在看到图之前就纠正物理理解**，
而不是等图画完了再说"不对"。

---

## 与 nature-figure 的关系

`nature-figure` 的 `core/contract.md` 有类似的"先写结论再写代码"（figure contract），
但它面向**数据图**，只到"core conclusion + evidence chain"这一层。

本 IR 的差别：

| | nature-figure contract | 本 IR |
|---|---|---|
| 面向 | 数据图 | **示意图 + 复合图** |
| 物理约束 | 无（它不需要） | **physics_role 强制填写** |
| 后端 | Python/R 二选一 | **多后端路由** |
| 元素级 | 无（到 panel 层） | **到图元层，含 z 序** |

## params 可执行化（v1.2 新增）

**问题**：原来 `elements[].params` 写的是中文散文 ——
`"约 0.34 画布宽"`、`"偏向右上，距介质中心约 0.21 介质半径"`。
→ **不可执行**，所以 `IR → 图` 这一步无法自动化，每张图都要人从零写脚本。

这跟当年 `geometry_constraints` 遇到的是**同一个问题**，同一种修法：
**把模糊描述逼成可计算的数值。**

### 新要求

```yaml
elements:
  - id: E1
    name: QGP 介质
    physics_role: >              # 散文留在这里（它的价值是解释，不是执行）
      碰撞产生的夸克胶子等离子体，喷注在其中传播并损失能量。
    primitive: qgp_blob          # ★ 必须是 cartoon_lib.PRIMITIVES 里的注册名
    params: {cx: 0.44, cy: 0.50, R: 0.185, ry: 0.78, seed: 5}
                                 # ★ 归一化数值，不是散文
    z: 1
```

### 归一化约定

| 参数 | 单位 |
|---|---|
| `cx` / `x` / `x0` / `x1` / `ox` | × 画布**宽** |
| `cy` / `y` / `y0` / `y1` / `oy` | × 画布**高** |
| `R` / `r` / `rx` / `w` / `L` | × 画布**宽** |
| `ry` / `h` | × 画布**高** |
| `seed` / `n` / `sep` / `glow` 等 | 原样传递 |

⚠️ **同名参数在不同图元里单位可能不同**。实测踩过：`ry` 在 `qgp_blob` 里是
**扁平比**（0.78），在 `lorentz_nucleus` 里是**纵向半径**（0.13）。
所以 `ir_to_scene.py` 的单位表是**按图元**声明的（`PARAM_UNITS`），不能按名字一刀切。

### 校验与生成

```bash
# 校验：primitive 在不在注册表、params 是不是数值、参数名在不在签名里
python3 scripts/ir_to_scene.py ir/xxx.ir.yaml --check

# 生成可运行的构图骨架（坐标已换算、按 z 序排好、图层已开）
python3 scripts/ir_to_scene.py ir/xxx.ir.yaml -o build_xxx.py
python3 build_xxx.py
```

`--check` 会报三类问题，每类都是实测踩过的：
1. `primitive` 不在注册表 → 生成时会调不存在的方法
2. `params` 是散文 → 无法换算
3. **参数名不在该图元的签名里** → 生成的调用会 TypeError
   （实测：`jet` 的签名是 `(x0,y0,x1,y1)`，IR 里写成了 `(x1,y1,x2,y2)`）

### 分层：图元 vs 构图

IR 里要分清两种元素：

- **图元层**（`primitive` 用注册名 + 数值 params）→ 可自动生成
- **构图层**（多元素的相对排布、阶段划分、面板布局）→ 仍需人/AI 写

`stage_*`、`spacetime_panel` 这类**是构图代码不是图元**，不该进图元库。
但可以把里面的算法母题抽成图元（已经抽了 `radial_rays` / `radial_arrows` /
`poisson_discs` / `light_cone` / `proper_time_family`）。

### 参考实现

`ir/sketch3_jet.exec.ir.yaml` —— 由散文版 `sketch3_jet.ir.yaml` 改写而来，
`--check` 通过，生成的骨架能直接跑出图。

## Scene Graph —— 位图 → 矢量的第三条路（2026-09-21）

### 问题

GPT/图像模型能从草图画出不错的**位图**，但**位图 → 矢量这一步它做不好**。
试过的两条路都不行：

| 路 | 为什么不行 |
|---|---|
| 像素描摹（`raster_to_vector.py`） | **没有理解**：文字碎成色块、渐变退化成色阶台阶 |
| 让模型看着位图重画 | **有理解但不忠实、不确定**：会漂移、会自己发明、两次不一样 |

### 第三条路

```
看懂这张图  →  建 Scene Graph  →  【确定性重组】  →  矢量
 （模型）      （模型，结构化）      scene_render.py
```

**理解力来自模型**（所以文字、公式、渐变、对象认得出），
**忠实度与可复现性来自"重组是代码"**。

### ★ 可复现性因此成立（且不是"同 prompt 两次一样"）

**同一份 Scene Graph → 逐字节相同的 SVG**（已实测验证）。
参考图库里的图只要 Scene Graph 定了，重组结果永远一致。

### 格式：在可执行 IR 上扩三样

```yaml
layers:                       # ★ 层级：有名字的组
  - {id: medium, name: "QGP 介质"}
  - {id: labels, name: "标注"}

elements:
  - id: E1
    layer: medium            # ★ 归属哪个层（不再靠 z 推）
    primitive: qgp_blob
    params: {cx: 0.44, cy: 0.50, R: 0.185, ry: 0.78, seed: 5}
    z: 1

  - id: T1
    layer: labels
    primitive: text          # ★ 文字是独立类型
    params: {x: 0.5, y: 0.08, t: "Global spin polarization", size: 17}

  - id: F1
    layer: labels
    primitive: formula       # ★ 公式：Unicode 直写，不用 LaTeX
    params: {x: 0.5, y: 0.9, t: "P_H = 0.052 ± 0.003", size: 13}
```

### 用法

```bash
python3 scripts/scene_render.py scene.yaml -o fig.svg --png fig.png --pdf fig.pdf
python3 scripts/scene_render.py scene.yaml --check
```

**校验会查**：primitive 认不认识、参数名在不在签名里、**必填参数漏没漏**、
`layer` 在不在 `layers` 里、id 有没有重复、有没有 `physics_role`。

### 提取 Scene Graph 的纪律

1. **几何量必须【量】，禁止【看】** —— 位置/尺寸从图上扫出来，不目测
2. **文字必须逐字抄对** —— 改成真 `<text>`，拼写数值不能错
3. **公式用 Unicode 直写** —— `ε₂(η) dN/dη ± ≈ ⟨⟩` DejaVu Sans 都有
4. **层级按语义分** —— 「介质/入射核/喷注/标注」，不是按颜色
5. **不确定的标出来** —— 看不清的地方宁可标 `# TODO: 待确认`，不要编

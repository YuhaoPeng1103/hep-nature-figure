# 3D 感检查清单 —— 一张示意图为什么立体 / 为什么不立体

> **用途**：画 T3（3D 示意图）之前逐条过一遍；图出来觉得"扁"时，按这张单子定位是哪一层塌了。
> **配套**：`references/ir-spec.md`（IR 里怎么写）· `references/svg-cookbook.md`（代码怎么画）
> **来源**：2026-10-01 ~ 10-02 用集体流示意图做的一整轮对照实验，全部有实测支撑。

---

## 0. 一句话

**"3D 感"不在渲染质量里，在投影里。**
一张图可以渲染得极其精致（柔和渐变、漂亮高光）**却完全不立体** ——
只要它的三轴关系是错的。反过来，一个纯色块只要投影对，一眼就是立体的。

---

## 1. ★★★ 第一层：投影 —— 「能不能立体」就死在这一层

这一层塌了，下面两层怎么补都是白费。**先查这里。**

| # | 必须成立 | 违反了会怎样 |
|---|---|---|
| **P1** | **视线不能沿主平面的法线** —— 要斜视 | 沿法线看 = 主平面正对读者 = 天生扁平，无解 |
| **P2** | **三条轴在画面上都不与水平/垂直重合** | x 水平 + y 竖直 = 等于没有投影 |
| **P3** | 主平面因此画成**斜的平行四边形**，不是矩形 | 矩形 = 一堵正对读者的墙 |
| **P4** | **法线轴要前缩**（明显短于另外两轴） | 法线轴与另两轴等长 = 自相矛盾 |

### ★ 最典型的错误（实测踩过，浪费了好几轮）

```
板（xy 面）正对读者   ← 画面上的矩形
      ＋
z 轴画成一根有完整长度的画面内箭头
      ↓
几何上不可能：xy 面正对读者 ⇒ z 是它的法线
              ⇒ z 只能画成 ⊙ 圆点，或一小截前缩的短桩
```

**只要 z 在画面里画得出长度，板子就必须是倾斜/前缩的。** 这两件事不能同时要。

### 实测锚点：T3-02 panel e 的三轴（Nature 2024，STAR）

| 轴 | 屏幕方向 |
|---|---|
| **y** | 竖直向上（89°） |
| **x** | 朝右上 **17°**（★ 不是水平） |
| **z（束流）** | 朝右下 **24°**，前缩 ≈ **0.72** |

**关键在 x 不水平** —— 所以 x-y 张成的横向平面必然是斜的平行四边形。
这是该图立体感的地基。

**另一个锚点（等轴测）**：T3-30 / T3-34 用三轴互成 ≈120° 的轴测，
主平面同样是斜的平行四边形，且**边平行于张成它的那两根轴的箭头**。

### 通用判据

> **平面的边，必须平行于张成它的那两根轴在画面上的方向。**
> 这条一破，读者就判断不出板子位于哪个平面。

### ★ 三轴方向怎么写才不会被画反（v4.0）

`composition.projection.轴方向_deg` 用的是**简报的约定**：

> **屏幕 y 向下。0° = 向右，90° = 向下，向上写负数。**
> （见 `references/ir-spec.md`、`scripts/ir_to_genbrief.py`）

★ **别直接把 `scripts/axonometric.py --check` 的读数填进去** —— 那个工具沿的是数学惯例
（**向上为正**），两者 y 反号。换算只有一步：

```
规范角（写进 IR） = −工具角        # 同一台相机、同一条轴
```

实测（`python3 scripts/axonometric.py --check --az 144.74 --el 45 --roll 118`，即 T3-02 那条线）：

| 读数 | x | y | z | 前缩 |
|---|---|---|---|---|
| `axonometric.py --check`（向上为正） | +17.00° | +88.56° | −28.00° | 0.8165 / 0.9129 / 0.7071 |
| **写进 IR 的 `轴方向_deg`（向下为正）** | **−17.00°** | **−88.56°** | **+28.00°** | 同上 |

★ v4.0 起 `--check` **两套角一起打**（右边一列标着「→ IR`），照抄那一列即可；
它还会顺手按 `projection_gate.py` 的 P1/P2 口径先自检（x/z 落在 0/±90、轴太挤、法线轴没前缩），
**画之前**就把「会被闸门拦」这件事报出来。
★ 另补了 `--roll` / `--level-axis`：默认 `--level-axis x` 会把 x 摆到 0°，正是 P1 禁的那种 —— 所以
要用别的轴当水平轴时**显式给** `--level-axis y` 或 `--roll`。

**填错的代价**：y 会被画成**竖直向下**（整张图像倒过来挂着），而且它**过闸门** ——
`projection_gate.py` 的 P1 只管「有没有落在 0 / ±90 附近」，反号的 y 照样合规
（y 本来就被允许竖直）。所以这一步只能靠人核：填完拿同一台相机把三条轴重新算一遍对账。

**另**：线条/箭头的方向也要按投影声明的角度画，**不要**按"看着像三维"随手挑 ——
随手挑出来的三轴方向 ≠ 任何一台相机，得到的正是第 4 节说的那种**斜投影**（`|r|≠1`、
`r·u≠0`），眼睛读它就叫「扁」。

## 2. ★★ 第二层：几何 —— 物体之间的空间关系

投影对了，还要让物体**真的处在同一个空间里**。

| # | 必须成立 | 少了会怎样 |
|---|---|---|
| **G1** | **物体穿过平面**（前后各露一半，有交线） | 物体像是"贴"在板前面 |
| **G2** | **遮挡顺序**：板边/网格线压在物体后半上 | 物体像是浮在板前面 |
| **G3** | **接触阴影**：物体在承接面上留下暗带 | 物体"浮"起来 |
| **G4** | 画序 = z 序（远的先画，近的后画） | 画反了元素凭空消失且不报错 |

**为什么 G1/G2 最重要**：它们是**唯一能把"这张平面"和"这些物体"钉在同一个空间里**的线索。
T3-02 panel e 里核的板后半边透过板面看得见、板的前缘压在核上 —— 就靠这个读出来"穿过去了"。

## 3. ★ 第三层：着色 —— 形体自身的体积

**这一层才是生图模型的强项**，也是唯一能靠措辞调的一层。

| # | 必须成立 |
|---|---|
| **S1** | **全图一个光源** —— 方位角 / 仰角写死，所有高光/明暗/投影从它推导（`cartoon_lib.py` 的 `LIGHT_AZIMUTH=128` / `LIGHT_ELEVATION=38`） |
| **S2** | 受光面 → 背光面的**连续明暗过渡**，不是平涂，也不是一圈淡淡的渐变 |
| **S3** | ★ **箭头必须是有厚度的实体**（圆柱杆 + 锥形头）。**细线承载不了 3D** |
| **S4** | **椭圆端面** —— 圆柱露出的那圈是椭圆，不是三角 |
| **S5** | 发光体（火球）**核心近白 → 中段 → 外缘**的连续过渡，不是同心色环 |

### ★ S3 单独说：为什么箭头总是第一个塌

生图模型对 **"arrow"** 的训练先验是**图示里的扁符号**。
球、地面、坐标轴它能白送 3D（摄影语料里自带透视），**箭头不行**。

**实测（A/D 两组，同一模型同一简报，只改 IR）**：

| 组 | IR 怎么说箭头 | 结果 |
|---|---|---|
| A | `conventions` 写明「有厚度的三维实体」 | **4/4 立体块箭头** |
| D | 没提箭头 | **4/4 细线 + 平三角** |

**所以：IR 里必须逐字写清箭头是实体**，不能指望模型自己想到。

**机理**：明暗渐变需要一个"面"来承载。细线没有面 —— 所以哪怕全图别的都对，
**箭头仍然会是 2D 的**。

## 4. ★★★ 谁在控制这些：着色能靠措辞，几何不能

这是整份清单里最实用的一条。

| 线索 | 能否用 prompt 控制 | 实测 |
|---|---|---|
| **着色线索**（第 3 层） | ✅ **能** | `--style-mode render3d` 有效 |
| **几何线索**（第 1、2 层） | ❌ **不能** | 把 z 的屏幕方向算到小数点后三位写进简报：**4 个 seed 里 1 个照做** |

**推论（决定了工作流）**：

```
第 3 层（着色）  → 交给生图模型，它强，而且 prompt 调得动
第 1、2 层（投影+几何）→ 必须【构造】出来：
                        · 要么代码直出（route 1：project() 就是投影本身）
                        · 要么把投影写进 IR，让简报把它当硬约束传下去
                        · 要么先算好线稿当 --content-ref（仍是软约束，需闸口兜底）
```

## 5. 用的时候怎么走

### 画之前（写 IR / 简报）
1. 过 P1–P4：视角写清了没有？三轴方向给数了没有？法线轴前缩了没有？
2. 过 G1–G4：物体穿不穿板？遮挡顺序写了没有？
3. 过 S1–S5：光源定没定？**箭头写成实体了没有？**

### 图出来觉得扁（定位用）
| 症状 | 塌在哪一层 |
|---|---|
| 板子看着是"正对读者的矩形" | **P1–P3** |
| 三轴和板子对不上（比如 z 有长度但板正对读者） | **P4** |
| 板子对了，但物体像贴在上面 | **G1–G3** |
| 什么都对，唯独箭头是细线 | **S3** |
| 形体没有明暗、每个元素各拍一个方向的光 | **S1–S2** |

### ⚠️ 不要做的事
- **不要靠"把轴画粗、加网格、加阴影"来救扁平** —— 前三层任何一层塌了，这些都是白费
  （实测：加粗轴 + 加板面网格 + 加接触阴影，全都没救回"板子正对读者 + z 有长度"这个矛盾）
- **不要指望换生图模型** —— 控制通道不变，换谁都会像上面那样自作主张

## 6. 相关：为什么"量"这件事也难

想给第 1 层加个机器闸口时，实测**两个手搓统计量都不成立**，记在这里免得重走：

| 探针 | 想法 | 为什么废 |
|---|---|---|
| **塑形覆盖率** | 量形体内部的低频亮度起伏，平的=0、有体积=几十 | 把**扁的**判成更有立体感（连通域把火球和板连成一片，大片平坦网格拉高中位数） |
| **边线方向直方图** | 按某投影画的图，边线方向只落在几个固定角度 | 在**代码矢量图**上完全正确（A 量出 0/90/45°、B 量出 28/151/90°），但**一到真图就废**：T3-30 真图 6.0%、T3-02 真图 6.8%，和生图模型的 5.7–9.3% 分不开 —— 它量的是**边缘锐利度**，不是投影一致性 |

**教训（与 `style-bench.md` 的四条陷阱同一条）**：
**手搓的图像统计量，必须先拿真参考图校准，再决定采不采信。**
两个探针都是"看起来很合理 → 校准后淘汰"。

用得上的是**局部**方法（在图上先检测出板子那个四边形，再量它的边方向），
而不是全图统计。
